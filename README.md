# ก้าว (kao-run)

แพลตฟอร์มรับสมัครงานวิ่ง monorepo นี้มี API (NestJS) และจะมีเว็บ (Next.js) ตามมา

- `apps/api` NestJS + Fastify, PostgreSQL 16 ผ่าน Drizzle/pg, Redis + BullMQ
- `docs/` สเปกระบบ: `blueprint.html`, `openapi.yaml`, `schema.sql`

## เริ่มใช้งานในเครื่อง

```bash
docker compose up -d                 # PostgreSQL 16 + Redis 7
cp apps/api/.env.example apps/api/.env
# ใส่ค่า JWT_SECRET, PII_ENCRYPTION_KEY, PII_HASH_KEY ตามคำสั่งในไฟล์
pnpm install
pnpm db:migrate                      # รัน apps/api/db/migrations/*.sql
pnpm db:seed                         # งานตัวอย่าง Riverside Night Run 2027
pnpm dev:api                         # http://localhost:4000/v1
```

คำสั่ง db และ dev อ่านค่าจาก environment ให้ export ค่าใน `.env` ก่อน (เช่น `set -a; . apps/api/.env; set +a`)

## Flow ที่ใช้งานได้แล้ว

| ขั้น | Endpoint |
|---|---|
| ดูงาน, ค้นหา (`q`, `province`, `month`, `type`, `distance` = short/10k/half/full/ultra, `open=1` เฉพาะที่เปิดรับและยังมีที่) | `GET /v1/events`, `GET /v1/events/filters` (จังหวัดและเดือนที่มีงาน), `GET /v1/events/:slug`, `GET /v1/events/:slug/availability` |
| เข้าสู่ระบบ (ชั่วคราว) | `POST /v1/dev/login` (เปิดเฉพาะ `ENABLE_DEV_ENDPOINTS=true`) |
| จองที่ 15 นาที | `POST /v1/checkout/sessions`, `GET`/`DELETE /v1/checkout/sessions/:id` |
| เลือก/เปลี่ยนไซซ์เสื้อ | `PUT /v1/checkout/sessions/:id/variants` (ก่อนสร้างคำสั่งซื้อ) |
| สร้างคำสั่งซื้อ | `POST /v1/orders` (ต้องส่ง `Idempotency-Key`) |
| ชำระเงิน | `POST /v1/orders/:id/payments` (`promptpay`, `card`, `mobile_banking`) |
| ยืนยันการจ่าย | `POST /v1/webhooks/payments/:gateway` |
| บัตรวิ่ง | `GET /v1/me/registrations`, `GET /v1/me/registrations/:id` |
| ผลการแข่งขันรวมทุกงาน (`q` ชื่องาน), ค้นหานักวิ่งข้ามงานด้วยชื่อหรือบิบ, ผลของฉัน | `GET /v1/results`, `GET /v1/results/search?q=`, `GET /v1/me/results` |

## Backoffice ผู้จัดงาน

ทุก endpoint อยู่ใต้ `/v1/org/:orgId` และตรวจบทบาทของผู้เรียกในทีมผู้จัดทุกครั้ง คนนอกทีมได้ 404

| งาน | Endpoint | บทบาทที่ทำได้ |
|---|---|---|
| ทีมผู้จัดของฉัน | `GET /v1/org` | ทุกคน |
| สมัครเปิดทีมผู้จัด (รอ KYC ผู้สมัครเป็น owner) | `POST /v1/org` | ทุกคนที่เข้าสู่ระบบ |
| KYC: ข้อมูลบริษัท เอกสาร บัญชีรับเงิน และสิ่งที่ยังขาด | `GET .../kyc` | ทุกบทบาท |
| แก้ข้อมูลบริษัท, อัปโหลด/ลบเอกสาร, ส่งบัญชีรับเงินให้แอดมินตรวจ | `PATCH .../kyc`, `POST .../kyc/documents` (multipart `type` + `file`), `DELETE .../kyc/documents/:docId`, `PUT .../bank-account` | owner |
| เปิดไฟล์เอกสาร KYC | `GET .../kyc/documents/:docId/file` | owner, admin |
| รายการงาน, ภาพรวม (ยอดรายวัน โควต้า เสื้อ รายได้) | `GET .../events`, `GET .../events/:id/dashboard` | ทุกบทบาท |
| สร้าง/แก้งาน, เปิด/ปิดรับสมัคร | `POST .../events`, `PATCH .../events/:id`, `POST .../publish`, `POST .../close` | owner, admin |
| ระยะ, ช่วงราคา | `POST/PATCH/DELETE .../races/:raceId`, `.../price-tiers/:tierId` | owner, admin |
| ไซซ์เสื้อและสต็อก | `PUT .../events/:id/shirts` | owner, admin |
| คูปอง | `GET/POST .../coupons`, `PATCH .../coupons/:couponId` | owner, admin (ดูได้ทุกบทบาท) |
| ฟอร์มสมัคร: คำถามเพิ่มเติม | `GET/POST .../questions`, `PATCH/DELETE .../questions/:questionId`, `PUT .../questions/order` | owner, admin (ดูได้ทุกบทบาท) |
| ผู้สมัคร: ค้นหา, รายละเอียด | `GET .../events/:id/registrations`, `GET /v1/org/:orgId/registrations/:id` | ทุกบทบาท |
| Export CSV, ดูเลขบัตรเต็ม | `GET .../registrations.csv`, `POST .../registrations/:id/reveal-id-doc` | owner, admin |
| บิบ: ภาพรวมช่วงเลข, ให้เลขเอง, ออกเลขให้คนที่ยังไม่มี, นำเข้า CSV | `GET .../events/:id/bibs`, `PUT .../registrations/:registrationId/bib`, `POST .../bibs/assign`, `POST .../bibs/import` | owner, admin (ดูได้ทุกบทบาท) |
| การเงิน: สรุปยอดงาน/ทั้งองค์กร, ธุรกรรม, Export CSV, รอบ payout | `GET /v1/org/:orgId/finance`, `GET .../events/:id/finance`, `GET .../finance/transactions`, `GET .../finance/transactions.csv` | owner, admin, finance |
| รับเสื้อและบิบหน้างาน, รายชื่อสำหรับออฟไลน์, ส่งคิวที่บันทึกตอนออฟไลน์ | `GET .../checkins/lookup?code=`, `POST .../checkins`, `GET .../checkins/roster`, `POST .../checkins/batch` | owner, admin, staff |
| คืนเงิน: รายการคำขอ, อนุมัติ, ปฏิเสธ, บันทึกโอนคืน, ยกเลิกสิทธิ์เอง | `GET .../events/:id/refunds?status=open\|closed`, `POST .../refunds/:refundId/approve\|reject\|transferred`, `POST .../registrations/:registrationId/cancel` | owner, admin, finance |
| ผลการแข่งขัน: สรุป, นำเข้า CSV (ตรวจก่อน), เผยแพร่ | `GET .../events/:id/results`, `POST .../results/import`, `POST .../results/publish` | owner, admin (ดูได้ทุกบทบาท) |
| ส่งข่าว: ร่าง, นับผู้รับ/ตัวอย่าง, ส่งทดสอบ, ส่งเลยหรือตั้งเวลา | `GET/POST .../events/:id/broadcasts`, `PATCH/DELETE .../broadcasts/:id`, `POST .../broadcasts/preview`, `POST .../broadcasts/:id/test\|send\|unschedule` | owner, admin |
| ทีมงาน: เชิญ, เปลี่ยนบทบาท, นำออก | `GET/POST /v1/org/:orgId/members`, `PATCH/DELETE .../members/:memberId` | owner (ดูได้ทุกบทบาท) |
| Waitlist: คิวแต่ละระยะ, เสนอที่ว่างทันที (เปิด/ปิดด้วย `waitlistEnabled` ใน `PATCH .../events/:id`) | `GET .../events/:id/waitlist`, `POST .../waitlist/offer` | owner, admin (ดูได้ทุกบทบาท) |
| โอนสิทธิ์ / เปลี่ยนระยะ: รายการของงาน, ย้ายระยะให้นักวิ่ง (ไม่เก็บเงิน) | `GET .../events/:id/changes`, `POST .../registrations/:registrationId/race-change` | owner, admin (ดูได้ทุกบทบาท) |

- **ไม่ลดเกินที่ขายไปแล้ว:** ลดโควต้าระยะ, โควต้าช่วงราคา หรือสต็อกเสื้อต่ำกว่าที่ขายหรือจองไว้ไม่ได้ ลบระยะหรือช่วงราคาที่มีคนซื้อแล้วก็ไม่ได้
- **การเงิน:** ยอดขาย (ค่าสมัครและสินค้าก่อนส่วนลด) − ส่วนลด − ค่าธรรมเนียมแพลตฟอร์ม − คืนเงินที่อนุมัติแล้ว = ยอดสุทธิของผู้จัด
  - ค่าธรรมเนียมแพลตฟอร์มคิดตอนสร้าง order จากตาราง `platform_fees` (อัตราขององค์กรก่อน ถ้าไม่มีใช้ค่า default ถ้าไม่มีเลย = 0) เป็น % ของยอดหลังส่วนลดบวกค่าคงที่ต่อผู้วิ่ง เก็บใน `orders.platform_fee_satang`
  - ค่าธรรมเนียมที่นักวิ่งจ่ายเพิ่ม (`RUNNER_FEE_BPS`) แยกแสดง ไม่รวมในยอดสุทธิ
  - รอบ payout (`settlements` / `payouts`) แอดมินสร้างและโอนให้ ผู้จัดเห็นอย่างเดียว Export ธุรกรรมบันทึกใน `audit_logs`
  - `pnpm db:seed` เพิ่มค่าธรรมเนียม default 3% เป็นตัวอย่างสำหรับเครื่อง dev
- **บิบไม่ชนกัน:** ช่วงเลขบิบของแต่ละระยะในงานเดียวกันห้ามทับกัน และเปลี่ยนเลขเริ่มไม่ได้เมื่อออกบิบไปแล้ว
  - เลขบิบไม่ซ้ำกันทั้งงาน (`uq_registrations_event_bib`) ใส่เลขที่มีคนใช้แล้วได้ `BIB_TAKEN` พร้อมเลขสมัครของเจ้าของเลข
  - ออกบิบอัตโนมัติตอนชำระเงิน และปุ่มออกเลขให้คนที่ยังไม่มี ใช้ฟังก์ชันเดียวกัน (`modules/bibs/next-bib.ts`) ข้ามเลขที่ให้เองหรือนำเข้าไปแล้ว
  - ให้เลขเองได้เฉพาะผู้สมัครที่ชำระเงินแล้ว ใส่เลขนอกช่วงได้ (VIP / นักวิ่งรับเชิญ) อักษรอังกฤษ ตัวเลข - ไม่เกิน 10 ตัว
  - นำเข้า CSV (คอลัมน์ `registration_no`, `bib` เช่นไฟล์ Export ที่กรอก bib แล้ว) ตรวจทุกแถวก่อน มีแถวผิดแถวเดียวไม่บันทึกเลย สลับเลขกันในไฟล์ได้
- **เปิดรับสมัครได้เมื่อพร้อม:** ต้องมีข้อมูลงาน สถานที่ ช่วงเวลารับสมัคร อย่างน้อยหนึ่งระยะ ทุกระยะมีราคา และทีมผู้จัดผ่าน KYC แล้ว
  - ผู้จัดที่ตั้งให้ต้องตรวจ (`organizations.review_events` ค่าเริ่มต้นของทีมใหม่) กดเปิดครั้งแรกแล้วงานเป็น `pending_review` รอแอดมินอนุมัติ หลังอนุมัติปิด/เปิดเองได้ ถ้าถูกส่งกลับ งานกลับเป็นร่างพร้อม `review.note`
- **รับของแบบออฟไลน์:** `GET .../checkins/roster` ส่งเฉพาะผู้สมัครที่ชำระแล้ว: เลขสมัคร บิบ ชื่อ ระยะ ไซซ์เสื้อ สถานะรับของ และมีคำขอคืนเงินค้างหรือไม่ ไม่มีเบอร์ อีเมล หรือเลขบัตร
  - QR ส่งเป็น SHA-256 ของ `qr_token` (หน้าเว็บ hash QR ที่สแกนแล้วเทียบ) รายชื่อที่หลุดไปจึงสร้างบัตรปลอมไม่ได้ ทุกการดาวน์โหลดบันทึกใน `audit_logs` (`checkins.roster_download`)
  - `POST .../checkins/batch` รับคิวไม่เกิน 200 รายการตามลำดับที่สแกน แต่ละรายการเป็น transaction ของตัวเอง ตอบผลรายตัว (`ok`, `replayed` หรือ `code` เช่น `ALREADY_PICKED_UP`, `REFUND_PENDING`, `NOT_CONFIRMED`, `REGISTRATION_NOT_FOUND`)
  - `clientUuid` เดิมส่งซ้ำได้ ไม่บันทึกซ้ำ (รวมถึงส่งพร้อมกันสองครั้ง) `scannedAt` เป็นเวลารับของจริงบนเครื่อง เวลาที่เกินปัจจุบันนับเป็นตอนนี้
- **คูปอง:** ล็อกส่วนลดเมื่อมีคนใช้โค้ดแล้ว แต่ยังปิดใช้หรือปรับจำนวนสิทธิ์ได้
- **คำถามเพิ่มเติม:** ข้อความสั้น/ยาว, ตัวเลข (กำหนดช่วงได้), เลือกหนึ่งหรือหลายข้อ, ติ๊กยืนยัน, วันที่ ถามทุกระยะหรือเฉพาะบางระยะ งานละไม่เกิน 30 ข้อ
  - หน้างาน `GET /v1/events/:slug` ส่ง `questions` ให้ฟอร์มสมัคร และ `POST /v1/orders` ตรวจคำตอบของนักวิ่งแต่ละคนตามระยะ (ตอบไม่ครบหรือผิดได้ 422 พร้อม path `participants.N.answers.<key>`) แล้วเก็บใน `registrations.answers`
  - คำตอบแสดงในรายละเอียดผู้สมัครและเป็นคอลัมน์ใน CSV
  - มีคนตอบแล้วเปลี่ยนประเภทไม่ได้ (`QUESTION_IN_USE`) ลบคำถามที่มีคนตอบแล้วจะแค่ซ่อน คำตอบเดิมยังอยู่
  - ยังไม่รองรับคำถามแบบอัปโหลดไฟล์
- **PDPA:** รายละเอียดผู้สมัครแสดงเลขบัตรแบบปิดไว้ การกดดูเลขเต็มและการ Export ทุกครั้งบันทึกใน `audit_logs`
  - CSV ไม่มีเลขบัตรและข้อมูลสุขภาพ และกันสูตร Excel (`=`, `+`, `-`, `@`)
- **รับของหน้างาน:** สแกน QR บนบัตรวิ่ง หรือพิมพ์เลขบิบหรือเลขสมัคร
  - รับของได้ครั้งเดียว ถ้าเครื่องสแกนส่งซ้ำด้วย `clientUuid` เดิมจะไม่บันทึกซ้ำ
  - ผู้สมัครที่ยังไม่จ่ายรับของไม่ได้
- **ผลการแข่งขัน:** นำเข้า CSV จากผู้จับเวลา (คอลัมน์ `bib`, `chip_time`, `gun_time`, `status`) จับคู่กับผู้สมัครที่ชำระแล้วด้วยเลขบิบ
  - แถวผิด (บิบไม่มี, บิบซ้ำ, เวลาอ่านไม่ได้, FIN ไม่มีเวลา) ไม่บันทึกเลย ส่วนเวลาผิดปกติ (เกิน cut-off, เร็วเกินจริง, gun น้อยกว่า chip) เป็นคำเตือน
  - ไฟล์ใหม่แทนที่ผลเดิมทั้งงาน คำนวณอันดับรวม เพศ และรุ่นอายุใหม่ทุกครั้งจาก chip time (ไม่มีใช้ gun) และคิด pace ต่อกม.
  - หน้าผลสาธารณะ `GET /v1/events/:slug/results?race=&q=&gender=` เปิดหลังผู้จัดเผยแพร่เท่านั้น (`RESULTS_NOT_PUBLISHED`) ค้นหาด้วยชื่อหรือบิบได้
  - `GET /v1/results` รวมงานที่เผยแพร่ผลแล้ว เรียงวันแข่งล่าสุดก่อน พร้อมจำนวนคนเข้าเส้นชัยต่อระยะ ส่วน `GET /v1/results/search?q=` หานักวิ่งข้ามทุกงาน (บิบตรงทั้งเลขขึ้นก่อน, ชื่อบางส่วน อย่างน้อย 2 ตัวอักษร, สูงสุด 50) ส่งกลับเฉพาะข้อมูลที่หน้าผลของงานแสดงอยู่แล้ว
- **ส่งข่าว:** ส่งอีเมลถึงผู้สมัครตามตัวกรองเดียวกับรายชื่อผู้สมัคร (ระยะ, ชำระแล้ว/รอชำระ, รับของแล้ว/ยังไม่รับ) แทรก `{ชื่อ}` `{บิบ}` `{ระยะ}` `{เวลาปล่อยตัว}` ได้
  - ตอนส่ง สร้าง `notifications` หนึ่งแถวต่อผู้สมัคร (กันซ้ำด้วย `dedupe_key`) แล้วส่งผ่าน BullMQ queue `notifications` ถ้ามี Redis ถ้าไม่มีส่งทันทีใน request
  - ข้อความที่ตั้งเวลาไว้ worker หยิบไปส่งทุก 30 วินาที และรอบเดียวกันจะส่งต่อให้ถ้ามีอีเมลค้างในคิวเกิน 5 นาที
  - ยังไม่มีผู้ให้บริการอีเมลจริง ใช้ `FakeEmailSender` (log และเก็บในหน่วยความจำ) ต้องเลือก provider และใส่ key ก่อนใช้จริง
- **คืนเงิน:** นักวิ่งดูยอดที่จะได้คืน (`GET /v1/me/registrations/:id/refund`) และส่งคำขอ (`POST .../refund-requests`) พร้อมบัญชีรับเงิน
  - คิดตามนโยบายของงาน (`allowRefund`, `refundPercentBps`, `refundDeadline` แก้ได้ใน `PATCH .../events/:id`) จากราคาที่จ่ายจริงหลังส่วนลด ค่าธรรมเนียมไม่คืน
  - ขอได้เมื่อจ่ายแล้ว ยังไม่รับของ และยังไม่เลยกำหนด (ไม่ตั้ง = ถึงวันแข่ง) ระหว่างรอผู้จัดตอบรับของหน้างานไม่ได้ (`REFUND_PENDING`) สิทธิ์หนึ่งมีคำขอค้างได้ครั้งละหนึ่ง
  - อนุมัติแล้ว: สิทธิ์เป็น `refunded`, คืนที่ของระยะ ช่วงราคา และไซซ์เสื้อ, ปล่อยเลขบิบ, บันทึกยอดค้างคืนที่ order และยกเลิกการใช้คูปองเมื่อ order ไม่เหลือสิทธิ์ที่จ่ายแล้ว
  - PromptPay คืนผ่าน gateway ไม่ได้ ผู้จัดโอนเองแล้วบันทึกเลขอ้างอิง (`succeeded`) เลขบัญชีเก็บแบบเข้ารหัส
  - ผู้จัดยกเลิกสิทธิ์เองได้ พร้อมคืนเงินเท่าไรก็ได้ไม่เกินที่จ่าย (0 = ยกเลิกไม่คืนเงิน)
- **สมัครเปิดทีมและ KYC:** ทีมใหม่เป็น `pending_kyc` และงานแรกต้องรอตรวจ (`review_events`) คนหนึ่งมีทีมที่รอ KYC ได้ไม่เกิน 3 ทีม (`TOO_MANY_PENDING_TEAMS`)
  - ข้อมูลบริษัท: ชื่อตามทะเบียน, เลขผู้เสียภาษี 13 หลัก (ตรวจเลขท้าย), จด VAT, อีเมล/โทร, ที่อยู่ หลัง KYC ผ่านแล้วแก้ชื่อตามทะเบียนและเลขผู้เสียภาษีไม่ได้ (`KYC_LOCKED`)
  - เอกสาร (`kyc_doc_type`): ต้องมีบัตรประชาชนผู้มีอำนาจและหน้าสมุดบัญชี ส่วนหนังสือรับรองบริษัทและ ภ.พ.20 สำหรับนิติบุคคล `readiness` บอกว่ายังขาดอะไร
  - ไฟล์ PDF, JPG, PNG ไม่เกิน 10 MB ตรวจชนิดจากเนื้อไฟล์ ไม่เชื่อนามสกุล (`UNSUPPORTED_FILE_TYPE`, `FILE_TOO_LARGE`) ทีมหนึ่งเก็บได้ 20 ไฟล์ ลบได้เฉพาะที่ยังไม่อนุมัติ
  - ไฟล์อยู่ใน storage ส่วนตัว (`STORAGE_DRIVER=local` เก็บใต้ `STORAGE_LOCAL_DIR`) ไม่มี URL สาธารณะ เปิดได้ผ่าน API ที่ตรวจสิทธิ์เท่านั้น ส่งแบบ `no-store` และทุกการเปิดบันทึกใน `audit_logs` ต่อ S3/R2 ได้โดยเพิ่ม driver ของ `FileStorage`
  - บัญชีรับเงินที่ owner ส่งยังไม่ตรวจ (`verified_at` ว่าง) จ่ายเงินเข้าไม่ได้จนแอดมินยืนยัน ส่งใหม่แทนอันที่รออยู่
- **ทีมงาน:** เชิญด้วยอีเมลและบทบาท คนที่ถูกเชิญเข้าทีมเองครั้งแรกที่ login ด้วยอีเมลนั้นแล้วเปิด `GET /v1/org` (ยังไม่มีลิงก์เชิญทางอีเมล)
  - ทีมต้องมี owner อย่างน้อยหนึ่งคนเสมอ ลดบทบาทหรือนำ owner คนสุดท้ายออกไม่ได้ (`LAST_OWNER`)
  - เชิญอีเมลซ้ำไม่ได้ (`ALREADY_INVITED`, `ALREADY_MEMBER`) ทุกการเชิญ ตอบรับ เปลี่ยนบทบาท และนำออก บันทึกใน `audit_logs`
- **Waitlist:** นักวิ่งเข้าคิวระยะที่เต็มได้ (`GET/POST /v1/me/waitlist`, `DELETE /v1/me/waitlist/:id`) เมื่อผู้จัดเปิดคิวของงาน
  - เข้าคิวได้เมื่อระยะเต็มหรือมีคนรอคิวอยู่แล้วเท่านั้น (`RACE_NOT_FULL`) หนึ่งคนเข้าคิวระยะหนึ่งได้ครั้งเดียว (`ALREADY_IN_WAITLIST`)
  - ที่ว่างจากยกเลิก คืนเงิน checkout หมดเวลา หรือเพิ่มโควต้า ถูกเสนอให้คิวตามลำดับใน job ทุก 30 วินาที (คืนเงินและยกเลิกเสนอทันที) และกันที่ไว้ใน `reserved` นาน `WAITLIST_OFFER_HOURS` (ค่าเริ่มต้น 24 ชั่วโมง) คนนอกคิวจึงแย่งไม่ได้
  - กดรับสิทธิ์ (`POST /v1/me/waitlist/:id/claim`) สร้าง checkout จากที่ที่กันไว้ (ไม่จองซ้ำ) จ่ายสำเร็จแล้วคิวเป็น `converted` ไม่ทันเวลาหรือสละสิทธิ์ ที่นั้นส่งต่อคิวถัดไป
- **โอนสิทธิ์:** เปิดด้วย `allowTransfer` (ค่าธรรมเนียม `transferFeeSatang` ผู้รับจ่าย, กำหนด `transferDeadline` ไม่ตั้ง = ถึงวันแข่ง) ใน `PATCH .../events/:id`
  - เจ้าของสิทธิ์ส่งให้อีเมลผู้รับ (`POST /v1/me/registrations/:id/transfers`) ระบบส่งอีเมลแจ้ง ผู้รับเห็นใน `GET /v1/me/transfers` เมื่อเข้าสู่ระบบด้วยอีเมลนั้น ต้องรับภายใน 7 วันหรือก่อนกำหนด
  - ผู้รับกรอกข้อมูลผู้วิ่งและคำตอบฟอร์มของตัวเอง (`POST /v1/me/transfers/:id/accept`) ตรวจอายุ/เพศของระยะและบัตรซ้ำในระยะ มีค่าธรรมเนียมได้ order ไปจ่ายก่อน ข้อมูลรอไว้ที่ transfer (เลขบัตรเข้ารหัส)
  - โอนสำเร็จ: สิทธิ์เดิมเป็น `transferred` (QR ใช้ไม่ได้) สร้างสิทธิ์ใหม่ `source = transfer` ที่ระยะ ไซซ์เสื้อ ราคา และเลขบิบเดิม เจ้าของเดิมไม่เห็นสิทธิ์นี้อีก
  - โอนไม่ได้หลังรับของ ระหว่างมีคำขอคืนเงิน หรือรอชำระเปลี่ยนระยะ และขอคืนเงินไม่ได้ระหว่างโอน ผู้ส่งยกเลิก (`DELETE /v1/me/transfers/:id`) หรือผู้รับปฏิเสธได้ก่อนสำเร็จ ค่าธรรมเนียมที่จ่ายเข้ามาหลังโอนไม่ได้แล้วคืนอัตโนมัติ
- **เปลี่ยนระยะ:** เปิดด้วย `allowRaceChange` (`raceChangeFeeSatang`, `raceChangeDeadline`) นักวิ่งดูตัวเลือกที่ `GET /v1/me/registrations/:id/changes`
  - `POST /v1/me/registrations/:id/race-changes` จองที่ในระยะใหม่ผ่าน checkout session (หมดเวลาตาม `hold_minutes` แล้วคืนที่) และสร้าง order ส่วนต่าง (ราคาที่เปิดขายตอนนี้ − ที่จ่ายไป) + ค่าธรรมเนียม ไประยะที่ถูกกว่าไม่คืนส่วนต่าง ไม่มียอดต้องจ่ายเปลี่ยนทันที
  - จ่ายแล้ว: ย้ายระยะ คืนที่ระยะเดิม ได้บิบใหม่จากช่วงของระยะใหม่ (บิบเดิมไม่ถูกนำกลับมาใช้) ที่ว่างในระยะเดิมเสนอให้คิว waitlist ก่อน
  - ระยะที่มีคนรอคิว waitlist อยู่เปลี่ยนเข้าไปไม่ได้ ขอคืนเงินภายหลังคิดจากค่าสมัครเดิม ส่วนต่างและค่าธรรมเนียมไม่คืน
  - ผู้จัดย้ายระยะให้ได้โดยไม่เก็บเงินและไม่ติดกำหนดของนักวิ่ง (ระยะใหม่ต้องมีที่ว่าง) ทุกการโอนและเปลี่ยนระยะบันทึกใน `audit_logs` และประวัติผู้สมัคร
- **ข้อมูลผู้วิ่งที่บันทึกไว้:** `GET/POST /v1/me/profiles`, `PATCH/DELETE /v1/me/profiles/:id` บัญชีหนึ่งเก็บได้ 20 คน คนละเลขบัตร (`PROFILE_EXISTS`) และเป็น "ตัวฉัน" ได้คนเดียว
  - เลขบัตรเก็บเข้ารหัส ส่งกลับแค่ 4 ตัวท้าย ตอนสมัคร (`POST /v1/orders`) หรือรับโอน ส่ง `profileId` แทนเลขบัตรได้ API อ่านเลขจากโปรไฟล์เอง (ใช้ได้เฉพาะโปรไฟล์ของตัวเอง)
  - `saveProfile: true` ในผู้วิ่งแต่ละคนบันทึกเป็นโปรไฟล์ (เลขบัตรเดิมอัปเดตคนเดิม) สิทธิ์ที่สมัครผูก `runner_profile_id` ไว้ ลบโปรไฟล์แล้วลบจริง สิทธิ์ที่สมัครไปแล้วยังมีข้อมูลของตัวเอง

- **Rate limit:** นับใน Redis (ทุก instance ใช้ตัวนับเดียวกัน ไม่มี Redis นับในหน่วยความจำของ instance) เกินแล้วได้ 429 `RATE_LIMITED` พร้อม `Retry-After` และ `retryAfterSeconds`
  - จำกัดต่อ IP และต่อผู้ใช้ (ถ้า login): login, ดูงานสาธารณะ (รายการ ค้นหา รายละเอียด ที่ว่าง ผล), คิว, สร้าง checkout, สร้าง order, สร้าง payment ค่าเริ่มต้นใน `RATE_LIMIT_POLICIES` (`src/common/rate-limit.ts`)
  - ต่อ IP ตั้งไว้กว้างเพราะเครือข่ายมือถือให้หลายคนใช้ IP เดียวกัน (CGNAT) ต่อผู้ใช้จึงเป็นตัวที่เข้มกว่า เช่น checkout 10 ครั้ง/นาที/คน

  - เว็บเรียก API จาก server เสมอ จึงส่ง IP ของผู้ใช้มาใน `x-kao-client-ip` คู่กับ `x-kao-proxy-secret` = `WEB_PROXY_SECRET` (ตั้งค่าเดียวกันทั้งสองฝั่ง) ไม่มี secret ที่ตรงกันจะใช้ IP ของผู้เรียกเอง

  - คิวเป็น sorted set ใน Redis (score = เลขลำดับที่เพิ่มทีละหนึ่ง เข้าพร้อมกันกี่คนลำดับก็ไม่ซ้ำ ดูลำดับด้วย ZRANK) คนรอนับหมื่นคนที่ refresh ทุกไม่กี่วินาทีจึงไม่ไปถึง Postgres
  - job `admit-waiting-rooms` ทุก `WAITING_ROOM_TICK_SECONDS` (5 วินาที) ปล่อยคนหน้าคิวตามอัตราของงาน ไม่มีงานไหนมีคิวก็แค่อ่าน set ว่างหนึ่งครั้ง ยังไม่เปิดรับสมัครยังไม่ปล่อย ผู้จัดปิด waiting room แล้วคิวถูกล้าง
  - ถึงคิวได้ token ที่เซ็นด้วย HMAC ผูกกับผู้ใช้และงาน อายุ `WAITING_ROOM_TOKEN_MINUTES` (10 นาที) ส่งใน header `X-Queue-Admission` ตอน `POST /v1/checkout/sessions` ไม่มี/ผิด = 403 `QUEUE_REQUIRED` หมดอายุ = 403 `QUEUE_TOKEN_EXPIRED` (เข้าคิวใหม่ได้) ตรวจ token ไม่ต้องใช้ Redis
  - token ที่ใช้เก็บใน `checkout_sessions.queue_token` รับสิทธิ์จาก waitlist ไม่ต้องเข้าคิว (มีที่กันไว้แล้ว) `POST /v1/dev/events/:eventId/queue/admit` ปล่อยคิวทันทีสำหรับ e2e
- **ผู้จัดตัวอย่าง:** `pnpm db:seed` สร้างบัญชี `organizer@riverside.example` เป็น owner ของผู้จัด Riverside (login ผ่าน `/v1/dev/login`)

## หลักการสำคัญในโค้ด

- **ไม่ขายเกินโควต้า:** ทุกการจองใช้ `UPDATE ... WHERE sold + reserved + n <= capacity` ครั้งเดียว ใช้กับระยะ, ช่วงราคา (Early bird) และไซซ์เสื้อ
- **จองก่อน ตัดจริงทีหลัง:** checkout ย้ายจำนวนเข้า `reserved` เมื่อจ่ายสำเร็จจึงย้ายไป `sold` ถ้าหมดเวลา job คืนโควต้าทุก 30 วินาที
- **จ่ายช้าหลังหมดเวลา:** ถ้ายังมีที่ว่างจะยืนยันให้ ถ้าเต็มแล้วจะสร้างรายการคืนเงินอัตโนมัติ
- **Webhook ซ้ำไม่มีผล:** บันทึก `webhook_events (gateway, event_id)` แบบ unique ก่อนทำงาน
- **Omise:** ไม่เชื่อ body ที่ส่งมา ดึง event กลับจาก Omise API ด้วย secret key ทุกครั้ง
- **PDPA:** เลขบัตรประชาชน/พาสปอร์ตเข้ารหัส AES-256-GCM และใช้ HMAC สำหรับตรวจสมัครซ้ำ
- **เงินเป็นสตางค์ (integer) ทั้งระบบ**

- flow เต็มตั้งแต่ดูงานจนได้บัตรวิ่งพร้อมเลขบิบ, คูปอง, ค่าธรรมเนียม
- 120 คนแย่ง 25 ที่พร้อมกัน → ขายได้ 25 พอดี, Early bird 10 ที่พอดี; ไซซ์เสื้อไม่ขายเกิน
- หมดเวลาแล้วคืนโควต้า, จ่ายช้าแต่ยังมีที่, จ่ายช้าแต่เต็มแล้วคืนเงิน
- Idempotency-Key, สมัครซ้ำด้วยบัตรเดิม, อายุไม่ถึง, webhook ปลอม
- Omise adapter (mock HTTP)
- ฟอร์มสมัคร: สร้าง/เรียงคำถาม, ตรวจคำตอบตามระยะ, คำตอบในรายละเอียดและ CSV, ล็อกประเภทเมื่อมีคนตอบ
- backoffice: สิทธิ์ตามบทบาท, สร้างงานจนเปิดรับสมัคร, กันลดโควต้า/สต็อกเกินที่ขาย, บิบทับกัน, คูปอง, ค้นหา/Export/audit, รับของหน้างาน, รายชื่อออฟไลน์และส่งคิว (ลำดับ, เวลาสแกน, ชนกับเครื่องอื่น, ส่งซ้ำ), ภาพรวม
- บิบ: ภาพรวม, ให้เลขเอง/ลบเลข, เลขซ้ำ, ออกเลขข้ามเลขที่มีคนใช้และหยุดเมื่อช่วงเต็ม, นำเข้า CSV (ตรวจทุกแถว, สลับเลข)
- คืนเงิน: ขอตามนโยบาย, บัญชีรับเงิน, กันรับของระหว่างรอ, อนุมัติแล้วคืนที่/ไซซ์/ช่วงราคา/คูปอง, ปฏิเสธ, บันทึกโอนคืน, ผู้จัดยกเลิกเอง, นโยบายและกำหนดเวลา
- ส่งข่าว: นับผู้รับตามตัวกรอง, แทนค่าในข้อความ, ส่งทดสอบ, ส่งแต่ละคนครั้งเดียว, ตั้งเวลา/ยกเลิก/ถึงเวลาแล้วส่ง, ส่งต่อที่ค้าง, สิทธิ์
- การเงิน: ค่าธรรมเนียมแพลตฟอร์มต่อ order, สรุปยอด (ส่วนลด คืนเงิน รอชำระ โอนแล้ว), ธุรกรรมตามสถานะ, CSV + audit, สิทธิ์ตามบทบาท
- ผลการแข่งขัน: ตรวจทุกแถว, คำเตือนเวลาผิดปกติ, อันดับรวม/เพศ/รุ่น และ pace, เผยแพร่/ซ่อน, ค้นหาผลสาธารณะ, นำเข้าไฟล์แก้ไข, สิทธิ์ตามบทบาท
- ผลรวมทุกงาน: แสดงเฉพาะงานที่เผยแพร่, เรียงวันล่าสุด, นับคนเข้าเส้นชัยต่อระยะ, ค้นหานักวิ่งด้วยชื่อและบิบ (ไม่เจอผลที่ยังไม่เผยแพร่), ผลของฉัน
- waitlist: ลำดับคิว, เสนอแล้วรับสิทธิ์จนจ่ายสำเร็จ, สละสิทธิ์ส่งต่อคิว, หมดเวลาคืนที่, หน้าคิวของผู้จัดและเสนอทันที
- สมัครเปิดทีมและ KYC: ทีมใหม่รอ KYC, จำกัดทีมที่รอ, เลขผู้เสียภาษี, ล็อกข้อมูลหลังผ่าน, อัปโหลด PDF/JPG/PNG (ชนิดจากเนื้อไฟล์, เกิน 10 MB, ไม่มีไฟล์), สิทธิ์เปิดไฟล์ (owner/admin ของทีม, staff ไม่ได้, คนนอก, ทีมอื่น, แอดมินแพลตฟอร์ม) + audit, แอดมินอนุมัติ/ส่งกลับทีละไฟล์แล้วผู้จัดลบและส่งใหม่, บัญชีที่ผู้จัดส่งรอแอดมินยืนยัน
- แอดมิน: สิทธิ์ตามบทบาท, งานแรกรอตรวจ/ส่งกลับ/อนุมัติ แล้วผู้จัดเปิดเองได้, KYC อนุมัติ/ระงับ/คืนสิทธิ์, บัญชีรับเงิน, รอบจ่ายต่อเนื่อง (ต้องมีบัญชี, โอนแล้วผู้จัดเห็น, ยกเลิกรอบแล้วยอดไปรอบถัดไป)
- ข้อมูลผู้วิ่ง: ไม่ส่งเลขบัตรกลับ, เลขบัตรซ้ำ, ตัวฉันคนเดียว, ของคนอื่นแก้/ลบ/ใช้สมัครไม่ได้, สมัครด้วยโปรไฟล์โดยไม่ส่งเลขบัตร, บันทึกตอนสมัครและอัปเดตคนเดิม
- ค้นหางาน: ช่วงระยะ, จังหวัด, เดือน, เปิดรับอยู่ (ไม่นับระยะที่เต็มหรือยังไม่เปิด), จังหวัดและเดือนที่มีงาน
- โอนสิทธิ์และเปลี่ยนระยะ: โอนฟรีจนบิบย้ายไปผู้รับ, นโยบาย/โอนให้ตัวเอง/อายุผู้รับ, ค่าธรรมเนียมจ่ายแล้วจึงย้าย หมดเวลากลับไปรอ ผู้ส่งยกเลิกแล้วคืนเงิน, เปลี่ยนขึ้นจ่ายส่วนต่างได้บิบใหม่, เปลี่ยนลงทันที, ที่ที่จองหมดเวลาคืน, ผู้จัดย้ายระยะ
- ทีมงาน: เชิญแล้ว login เข้าทีม, เชิญซ้ำ, owner คนสุดท้าย (รวมสอง owner ลดบทบาทกันพร้อมกัน), ถอนคำเชิญ
- rate limit: 429 + `Retry-After` เมื่อเปิด, สอง instance ใช้ตัวนับเดียวกัน (เมื่อมี Redis), IP ที่ส่งต่อเชื่อเฉพาะเมื่อ secret ตรง, จำกัดต่อผู้ใช้, ปิดได้, ไม่มี Redis นับในหน่วยความจำ
- waiting room: ลำดับ/ตำแหน่ง/เวลารอ, ปล่อยตามอัตราในแต่ละรอบ, ยังไม่เปิดไม่ปล่อย, checkout ต้องมี token (ไม่มี ปลอม ของคนอื่น ของงานอื่น หมดอายุ), 60 คนเข้าพร้อมกันลำดับไม่ซ้ำ, ปิดแล้วล้างคิว, ผู้จัดตั้งค่า, production ไม่มี Redis เปิดไม่ได้

test ของ waiting room และ rate limit ใช้ Redis จริงถ้าต่อได้ (`TEST_REDIS_URL` ค่าเริ่มต้น `redis://127.0.0.1:6379` แยก key ด้วย prefix สุ่มต่อรอบ) ต่อไม่ได้จะใช้ตัวเก็บในหน่วยความจำแทน
